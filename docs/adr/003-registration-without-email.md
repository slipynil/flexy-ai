# ADR-003: Регистрация аккаунтов без подтверждения почты

- **Статус:** Принято
- **Дата:** 2026-11-05

## Контекст и проблема

После инцидента на хостинге Beget (кибератака 1–2.11.2026, восстановление инфраструктуры)
аккаунты старого пула перестали работать. Параллельно flexy-ai.com отключил проверку
email при регистрации: письмо-подтверждение не отправляется, аккаунт полноценный
сразу после отправки формы.

Старый путь регистрации (`register_accounts` в `src/farm.py`) завязан на temp-mail.org
+ undetected-chromedriver: медленный (запуск браузера на каждую попытку), хрупкий
(Cloudflare, флап temp-mail) и больше не нужен — верификационной ссылки просто нет.
При этом проверка почты может вернуться в любой момент, поэтому старый путь
обязан остаться рабочим.

## Решение

Второй путь регистрации рядом со старым (старый не удаляем и не меняем):

- `register_accounts_no_email(count)` в `src/farm.py` — pure requests, без браузера
  и temp-mail: случайная почта (`generate_random_email()`, домены из
  `RANDOM_EMAIL_DOMAINS` в `src/config.py`; коллизия лечится повтором с новым
  адресом) → `register_user()` → `FlexyAiAPI.login()` сразу после регистрации
  (с ретраем при флапе токена, по образцу `verify_and_get_api_key`) →
  `api_key = "{mail}:{token}"` (формат действующего пула) → `DB.add_account()`.
- Новая точка входа `scripts/run_register_accounts_no_email.py` + задача mise
  `register_accounts_no_email` + пункт в UI-меню.
- Для утилизации мёртвых аккаунтов старого пула — `DB.clear_accounts()` + пункт
  «Очистить пул» в UI (локальное расширение репозитория и UI, отдельного ADR
  не требует).

### Попутно починен обмен с flexy-ai.com после восстановления сайта

Сайт восстановлен из бэкапа на техническом домене Beget, и его формы
изменились — без этих правок не работал ни старый, ни новый путь:

- **Формы ARMember**: состав полей динамический (arm_action стал
  `please-signup`/`please-login`, протухли дефолтные ключи форм 101/102/103).
  Поля и ключи парсим со страницы (`src/parse_files.py::get_arm_form_fields`,
  `src/flexy_ai/registration.py::reinit_forms`).
- **Анти-бот сабмита**: `form_random_key` = data-random-id формы (не значение
  reinit), обязательны `form_filter_st`/`form_filter_kp`, honeypot
  `arm_filter_input` не отправляется, 8-символьный ключ reinit — имя
  обязательного пустого поля; сабмит раньше ~10 сек с загрузки страницы
  отклоняется («Обнаружен спам») — дозасыпаем `ARM_FORM_FILL_DELAY_SECONDS`.
- **API генерации переехал** на `https://api.flexyai.ru` (старый путь
  `flexy-ai.com/api/*` отвечает 302 на главную). Формат ключа `mail:token`
  остался прежним — пул не менялся.

## Рассмотренные альтернативы

1. **Заменить старый путь новым** — отклонено: проверка почты может вернуться,
   temp-mail-путь тогда снова станет единственным рабочим.
2. **Только пункт в UI, без отдельного скрипта/mise-задачи** — отклонено: по
   ADR-002 UI и CLI равноценны, регистрация нужна и из пайплайнов/скриптов.

## Последствия

**Плюсы:**
- регистрация перестает зависеть от Chrome, chromedriver и temp-mail.org;
- секунды на аккаунт вместо минут (нет запуска браузера и ожидания письма);
- старый путь сохранен для возврата верификации.

**Минусы / цена:**
- два пути регистрации в `farm.py` — оба держать в рабочем состоянии;
- если flexy-ai вернет проверку почты, новый путь начнет падать на входе после
  регистрации (прерывается с понятной ошибкой, старый путь продолжает работать).
