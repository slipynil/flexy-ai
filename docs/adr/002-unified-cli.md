# ADR-002: Единый интерактивный CLI (меню запуска скриптов)

- **Статус:** Принято (реализовано в этом же коммите)
- **Дата:** 2026-11-01
- **Связан с:** ADR-001 (завершает его фазу 2 — ферма регистрации переезжает в `src/`)

## Контекст и проблема

Запуск любой функции проекта — это отдельная команда с флагами, которые надо помнить:

```bash
mise run bot
mise run register_accounts -- --counts 5
mise run generate_txt2img -- --prompt "..."
mise run generate_ctx2img -- --imagepath f.jpg
```

Оператору неудобно: команды легко забыть, флаги перепутать, готового «пульта» нет.

## Решение

Единое интерактивное CLI-приложение `scripts/run_ui.py` (запуск: `mise run ui`):

- меню со стрелками на [questionary](https://github.com/tmbo/questionary): бот,
  txt2img, ctx2img, регистрация N аккаунтов, выход;
- оформление на [rich](https://github.com/Textualize/rich): панели, статусы-спиннеры,
  цветные результаты и ошибки;
- UI — только представление: доменная логика вызывается из `src/`
  (`generation`, `farm`), ничего не дублирует;
- старые точки входа и mise-задачи сохраняются (UI — надстройка, не замена).

Попутно завершена фаза 2 ADR-001: логика фермы перенесена из
`run_register_accounts.py` в `src/farm.py` (`register_accounts(count)`),
потому что UI нужен программный вызов, а не только CLI.

### Формат запуска внутри UI

| Пункт меню | Что делает |
|---|---|
| 🤖 Запустить Telegram-бота | `asyncio.run(run_bot.main())`, Ctrl+C — возврат в меню |
| 📝 Генерация: текст → изображение | ввод промпта → `generation.text_to_image` |
| 🖼️ Генерация: изображение → изображение | ввод пути к файлу (с валидацией) и промпта → `generation.context_to_image` |
| 👥 Регистрация аккаунтов | ввод количества → `farm.register_accounts(count)` |
| 📊 Пул аккаунтов: доступные и попытки | статистика пула (read-only) → `repository.DB.get_pool_stats()` |

## Рассмотренные альтернативы

1. **Textual (полноценный TUI-фреймворк)** — избыточен: нужны панели/спиннеры,
   а не приложение с виджетами и своей event loop; тяжелее в поддержке.
2. **Нумерованное меню на input()** — нет красоты/удобства, ради которых всё затевалось.
3. **UI запускает скрипты через subprocess** — потеря логов в общем формате,
   проблемы с Ctrl+C; выбран прямой импорт сервисов.

## Последствия

**Плюсы:**
- один вход для оператора: `mise run ui`, ничего помнить не надо;
- валидация ввода на месте (число аккаунтов, существование файла);
- завершение фазы 2 ADR-001: ферма тестируема отдельно от CLI.

**Минусы / цена:**
- +2 зависимости (`rich`, `questionary`);
- интерактивное меню требует TTY (в CI/пайплайнах — использовать старые mise-задачи).
