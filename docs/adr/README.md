# ADR — Architecture Decision Records

Каталог архитектурных решений проекта flexy_service.

ADR фиксирует **почему** принято решение, а не только что сделано. Код можно переписать,
ADR — это история, которая не даёт перечитать старые грабли.

## Процесс

1. **Перед значимыми изменениями** сверься с существующими ADR — решение, возможно, уже принято. Следуй ему или предлагай изменить через новый ADR, а не молча в коде.
2. **Глобальные изменения оформляй новым ADR до реализации**: новые внешние системы, изменение границ модулей/слоёв, смена ключевых библиотек, изменения схемы БД или логики пула аккаунтов, новые точки входа.
3. Локальные правки в рамках принятых решений ADR не требуют.
4. **Формат**: Контекст → Решение → Рассмотренные альтернативы → Последствия (плюсы/минусы). Отложенные вещи — явно, с причиной.
5. **Статусы**: `Предложено` → `Принято` / `Отклонено`; `Заменён ADR-XXX` — если решение пересмотрено.
6. **Номер** = max существующий + 1, файл `NNN-короткое-имя.md`. Принятые ADR не редактируются задним числом — новое решение пишется новым ADR со ссылкой на старый.
7. После реализации обнови индекс ниже; при изменении структуры — `README.md` и `docs/c4-model.md`.
