# ADR-001: Пересмотр модульности — сервисный слой генерации

- **Статус:** Принято (фаза 1 реализована в этом же коммите)
- **Дата:** 2026-11-01

## Контекст и проблема

Проект вырос из набора скриптов, и модульность за ним не поспевала:

1. **Дублирование доменной логики.** Сценарий «захватить аккаунт → login → генерация →
   списание tries / cooldown при rate-limit» был скопирован трижды:
   `scripts/run_bot.py (ctx2img)`, `scripts/run_generate_txt2img.py`, `scripts/run_generate_ctx2img.py`.
   Копии уже расходились: CLI не умел перебирать аккаунты при блокировке, а бот умел.
2. **Точки входа тянули домен.** Скрипты импортировали `DB` и `FlexyAiAPI` напрямую —
   переиспользовать и тестировать логику без бота было нельзя.
3. **Константы размазаны.** `DEFAULT_PROMPT` жил в трёх файлах, `ACCOUNT_COOLDOWN_SECONDS` — в боте.
4. **Смешение ответственности.** `scripts/` содержали одновременно оркестрацию и бизнес-логику.

## Решение

Разделить: **тонкие точки входа** (argparse + вызов src) и **сервисный слой** в `src/`.

```
scripts/              # только запуск: парсинг аргументов, вызов сервиса
src/
  config.py           # общие константы (DEFAULT_PROMPT, ACCOUNT_COOLDOWN_SECONDS)
  generation.py       # сервис генерации через пул аккаунтов (единственная реализация сценария)
  flexy_ai/           # HTTP-клиент API + регистрация
  repository/         # пул аккаунтов (SQLite)
  ...                 # остальное без изменений
```

### Что сделано (фаза 1)

- Создан `src/generation.py`: `context_to_image()`, `text_to_image()`, общий
  `_generate_with_pool()` — перебор аккаунтов, cooldown, списание tries.
- Создан `src/config.py` — общие константы в одном месте.
- `run_bot.py` больше не знает про `DB` и `FlexyAiAPI` — только хендлеры aiogram
  и вызов сервиса через `asyncio.to_thread`.
- CLI-скрипты сокращены до argparse + вызов сервиса; поведение уравнено с ботом
  (перебор аккаунтов теперь есть и в CLI).
- Попутный фикс: `FlexyAiAPI.text_to_image()` теперь возвращает путь к файлу,
  как и `context_to_image()` (раньше терял его).

### Отложено (фаза 2, backlog)

- Извлечение фермы регистрации из `run_register_accounts.py` в `src/farm.py` —
  осознанно отложено: скрипт работает, выгода ниже стоимости перетряски.
- Переименование `parse_files.py` → `flexy_ai/form_parser.py` (имя не отражает суть).
- Группировка `convert_image.py` + `save_base64_image.py` в `src/images/`.
- DI/интерфейсы для тестов (сейчас — подмена атрибутов модуля в тестах).

## Рассмотренные альтернативы

1. **Оставить как есть** — дублирование уже привело к расхождению поведения CLI и бота;
   каждое изменение логики ротации пришлось бы вносить в три места.
2. **Полная перепаковка пакетов сразу** (farm, images, переименования) — высокий риск
   без интеграционных тестов; решение отложено в фазу 2.

## Последствия

**Плюсы:**
- единая точка изменения логики ротации/пула;
- CLI и бот гарантированно ведут себя одинаково;
- сервис легко покрыть unit-тестами подменой `FlexyAiAPI`/`DB`;
- точки входа стали читаемыми (~50 строк вместо ~100).

**Минусы / цена:**
- лишний уровень косвенности: точка входа → сервис → API (считаем приемлемым);
- документацию (README, c4-model) нужно держать актуальной — правило занесено в AGENTS.md.
